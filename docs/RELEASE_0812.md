# 0.8.12：后台验证到正式播放的会话交接（已安装，公网电影问题未解决）

0.8.11 安装版真实搜索 458 条，后台有一条解码成功并置顶，但点开首项时新建会话、重新下载，60 秒内再次失败。证据 `evidence/v0811/installed-search.json` 与 `installed-movie.json`。因此后台首帧成功不能单独作为交付验收，必须再点击同一结果验证。

## 修正

- 后台首次解码成功后，保留一个会话最多两分钟，并停止继续占用网络检测其他候选。标签在会话准备好之后才更新。
- 按规范化资源哈希或具体种子地址匹配，只能接管同一个资源；正式播放器接管已有连接和校验数据，不重新下载或重复试播。
- 正式播放解除后台 512 KiB/s 检测限速；保留旧的整体超时、校验边界和实际解码判定。
- 新搜索、过期、手动进入空播放器和退出清理保留会话；过期会撤销其可播排序证据。播放器接管后，缓存管理器不能再清理它，改由播放器停止/关闭负责。
- 来源配置、玻璃界面布局和现有播放器控件保持。

## 验收

新增资源身份、一次性交接、无新下载会话、真实画面继续播放、移交后原缓存管理器无权释放、停止清理、两分钟过期释放与排序失效等检查。最终完整构建回归退出码0，89项播放检查通过（`build.log`）。0.8.11 的新下载层磁力/种子/MKV和公网两分钟播放证据继续适用，本次重点补交接和安装版真实首项播放。

测试中一次原有本机种子夹具下载过快，首次观察画面时已下载完成，无法证明边下边播。保留失败日志，将测试做种限速从 1 MiB/s 调到 512 KiB/s 后重测，未放宽“未下完就播放”的断言，产品下载限速未改变。

## 仍未解决

用户公网电影快速起播仍未达到要求，不能宣称排在最前面的全部都能播放。当前只把实际解码成功的资源置于最高层；零成功时明确显示“暂无已验证可播资源”，有数据/未知/失败分开。下一步需针对本次有校验数据却未解码的同一哈希，记录请求位置、首片/索引等待和真实解码耗时，比较单候选与并发限速条件，不能继续仅靠增加网站或延长无限等待。
