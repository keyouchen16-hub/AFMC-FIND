# AFMC FIND 0.8.9

## 本次变更

播放器普通窗口和全屏都没有固定标题栏、视频外框或内容边距；窗口控件移入视频覆盖层，随播放控制栏显隐。顶部显示版本号及最小化、最大化/全屏、关闭按钮，可拖动顶部空白。地址栏与文件列表在画面内展开。留黑区域使用纯黑底，关闭 DWM 细边线与圆角，不修改系统全局设置。等待提示缩短，完整版本仍在底部状态中。

搜索完成后检测当前可见结果前 3 个影视/动漫条目，每次最多两个并发，每路后台下载限速 512 KiB/s；保留已有 25 秒单次和 60 秒整组预算。首次真实解码成功即停止其他探测，释放胜出探测会话（后台不弹播放器）。重新搜索和开始播放取消旧探测；正式播放不受后台限速影响。未安装解码运行时时跳过后台探测，不自动下载播放器组件。

实测证据按资源哈希（无哈希时使用种子地址）记录在本次应用会话内，30 分钟过期。实际解码成功标为已验证可播；TorrentManager.Progress 大于零代表已校验分片，标为已验证有数据但播放未确认；超时和播放失败不代表不可下载。用户主动取消不记录失败。综合排序在相关度基础上给予有限加权，手动排序不变。检测时间显示在结果说明中。

## 验收与修复记录

普通窗口无边框/边距、输入控件覆盖视频、证据按哈希隔离和过期、下载数据与可播区分加入播放检查。真实候选解码、取消、关闭、寻址、全屏回归保留。

首轮失败记录保存在 evidence/v089/playback-first-failure.log：播放器纯黑底与通用对话框磨砂断言冲突。最终播放器采用纯黑底的独立断言，其余对话框继续验证共享磨砂。实际截图曾发现留黑区域透出灰底，故以纯黑底修正，而非仅删除断言。

工作台首次失败记录在 workbench-first-failure.log：等待后台清理导致窗口没有立即打开。改为先展示窗口，再在准备播放前等待后台退出，后续工作台检查通过。

## 边界

不是全网可用性证明；短时间可播不保证全片无卡顿，超时不判定死种。后台只测有限候选，不逐条证明全部结果；压缩包/格式不支持仍显示未确认或本次失败，不冒充“可以完整下载”。本轮未用用户公网电影验证速度。网络错误不向用户泄露链接中的凭据。

最终安装及验证结果见 PROJECT_STATE.md 和 evidence/v089。

最终候选验证：75 项播放、63 项工作台、46 项完整性检查通过。源码截图经实际查看，黑色留边及窗口内部悬浮按钮符合要求。播放器跳过通用 DialogGlass 的整窗 backdrop 初始化，保留其他窗口原有行为；没有采用修改系统 static 窗口类的全局方案。截图增加边缘 RGB <=20 的真实像素断言。
