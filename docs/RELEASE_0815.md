# 0.8.15 播放器窗口拖动修正（2026-11-05，已安装）

用户确认残影出现在拖动整个窗口。保留现有播放器外观、播放引擎与硬件解码配置，只调整移动期间覆盖层绘制。

## 证据与修正

LibVLCSharp.WPF 3.10.2 用单独的透明窗口承载控制层，随视频窗口位置变化对齐；依据[对应版本 ForegroundWindow 源码](https://raw.githubusercontent.com/videolan/libvlcsharp/3.10.2/src/LibVLCSharp.WPF/ForegroundWindow.cs)。基线实际鼠标拖动捕获空闲状态两层最多 14 像素错位；播放中该次测试没有同样错位。窗口外侧采样（排除 20 像素阴影区）没有检出持续残留，因此不能声称已完全复现用户所述明显残影。

WM_ENTERSIZEMOVE 到 WM_EXITSIZEMOVE 期间仅将覆盖窗口不透明度置零，保留 HWND、鼠标拖动和视频播放；结束时在视频新位置对齐后恢复原透明度。DragMove finally 兜底恢复。曾尝试直接隐藏 HWND，但实际鼠标拖动被 Windows 中断，已弃用并保留失败证据。

四轮真实输入测试（空闲两次、播放两次）通过：窗口实际移动、控制层在移动时不绘制、结束位置一致并恢复显示、播放时钟持续前进；窗口外侧采样未检出残留。evidence/player-drag/after-opacity/drag.json 及截图。仅覆盖当前显示器 150% 缩放，非全部显卡/多显示器/刷新率矩阵；动态截图采样不是逐刷新帧录屏。

诊断入口 `--player-drag` 使用项目隔离配置与原创 AVI/回环视频，屏幕输入只发往检测为本测试进程的窗口。系统 PATH 的 dotnet 没有 SDK，使用 `.tools/dotnet/dotnet.exe` 固定 10.0.403；未安装或修改全局工具。
